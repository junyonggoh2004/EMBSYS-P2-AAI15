# Configurable ESP32-S3 firmware — ESP-IDF / µT-Kernel SMP

This target uses main's complete configurable framework at upstream commit `49677c62c8738493f4e66667d1fe79afc947600d`, with optional AHT and TSL2561 I²C profiles and the existing asynchronous GPIO pulse driver. See the [branch README](../README.md) for the full wiring tables, Windows build/flash/monitor instructions, preset commands and JSON formats. [WIRING.md](WIRING.md) contains the same complete connection tables.

The corrected firmware now has user-provided board evidence of all three sensors returning OK/error 0 together; see [VALIDATION.md](VALIDATION.md). The earlier shared breadboard LCD showed a dim/white screen. The separate opt-in `LCDTEST` now produces the intended colour bands and white `LCD READY` with inversion `0`; after the stack-buffer fix, `BenchmarkTask` showed 1740 B free on the board. For an LCD-only test, follow the [separate breadboard wiring table and images](WIRING.md#separate-lcd-only-breadboard-test-current-lcd_output-firmware) and [LCD component guide with test photos](components/lcd_output/README.md#hardware-and-test-images); the older shared-fixture GPIO6/7/8/9 LCD wiring does not match the current driver. The three-sensor preset does not invoke `LCDTEST`. Upstream SPI flash diagnostics use another fixture and must not be run with the LCD attached.

Build with `tools/build.ps1 build`, flash with `tools/build.ps1 flash -Port COMx`, load the volatile three-sensor configuration with `tools/build.ps1 sensors -Port COMx`, then open `tools/build.ps1 monitor -Port COMx`. The helper loads `../config/three_sensors.cfg` via the existing command interface and STOP/CLEAR replaces volatile sensor/rule configuration. Without a preset, configure and RUN manually. Ctrl+C leaves the interactive monitor.

The default output folder is `build/`, separate from the previous sensor-only `build_mtk/`. A `-BuildDirectory` override permits a shorter output path on Windows. CMake uses response files and limits the SDK to the application's dependency closure; all shared components and the full runtime remain compiled. `tools/audit_configurable.py` audits the actual ELF and compiler inputs after every successful build.

An optional `tools/local.env.ps1` can point to the installed ESP-IDF, toolchain and kernel; it is ignored by Git. The current LCD test session used `MTKERNEL_PATH`, `IDF_PATH`, `IDF_TOOLS_PATH` and `IDF_PYTHON_ENV_PATH` environment variables instead. Other machines must initialise the kernel submodule or configure an external kernel path, install the qualified ESP-IDF revision/Python requirements/tools, and create their own local settings. Exact SDK/kernel commits are in `dependencies.lock.json`; managed MQTT/TFLite dependencies remain pinned by main's `dependencies.lock`. The kernel source is the same revision used by main, and it is not modified by this integration.

Main's memory layout requires 2 MB quad PSRAM and 4 MB flash, including the fixed model partition. µT-Kernel owns the seven framework tasks, two idle tasks, message buffers, mutexes, alarms and supervision; the SDK compatibility shim does not run the FreeRTOS scheduler. SchedulerTask and its GPIO ISR are on physical CPU1, MQTTTask on CPU0. A `TASKS` capture from the LCD test showed the runtime tasks and stack headroom; combined sensor operation with the LCD remains a separate check.

See [MAIN_COMPONENT_REVIEW.md](../MAIN_COMPONENT_REVIEW.md) for the analysis completed before updating the workspace, [MTK_REDESIGN.md](../MTK_REDESIGN.md) for main's runtime/memory design, and [VALIDATION.md](VALIDATION.md) for actual checks and remaining board validation.
