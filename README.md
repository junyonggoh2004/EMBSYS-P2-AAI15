# D1 — Port configpico2wedge to ESP32-S3

Branch: `s3-port`. The Pico 2 W build is kept only as the reference that ESP32-S3 parity is measured against.

Build and flash instructions are in [SETUP.md](SETUP.md). The framework's configuration syntax and command reference are in [project_v3/README.md](project_v3/README.md).

## Checklist

Tasks are ordered by dependency: each one relies on the tasks before it.

| #   | Task                                           | What we do                                                                                                                                                                                                                                    | How we verify it                                                                                                              | Why it matters                                                                                                                                          | Status      |
| --- | ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- |
| 1   | Clean the workspace                            | Set aside unused debug edits in `gpio.c`, delete the stale `build/` folder, and add clangd's `.cache/` to `.gitignore`.                                                                                                                       | `git status` shows no unexpected changes.                                                                                     | Every later step starts from a known state, and `.cache/` is a machine-specific index that must never be committed.                                     | Done        |
| 2   | Create `s3-port`                               | Branch off `Pico_Sample`, the supplied framework, then restore the missing TFLite Micro submodule, add SETUP.md with corrected HC-SR04 wiring, and move the framework reference to `project_v3/README.md`.                                    | Every commit shows its real author, the submodule is recorded, and nothing from other branches is included.                   | One branch carries both the reference build and the port. Porting the unmodified framework means any Pico to S3 difference can only come from the port. | Done        |
| 3   | Rebuild the Pico reference                     | Configure a fresh `build/` with Arm GCC 14.2 and build.                                                                                                                                                                                       | `Built target project_v3`, and `project_v3.uf2` is produced.                                                                  | Proves the baseline compiles before its behaviour is trusted.                                                                                           | Done        |
| 4   | Retest every framework feature on the Pico 2 W | REPL commands; GPIO digital, pulse (HC-SR04 at 5 V with the Echo divider and `gpio.mode=pulse`), counter and onewire; an I2C sensor; a UART sensor; one rule; MQTT if a broker is available.                                                  | Each feature gives the expected output, and the HC-SR04 pulse width changes with distance.                                    | Parity can only be claimed for features shown working on the Pico first.                                                                                | Not started |
| 5   | Write the parity checklist                     | One row per feature, recording the Pico result and the exact config command used.                                                                                                                                                             | Every row has a result and a command.                                                                                         | This becomes D1's parity table, and reusing the identical command on the S3 keeps the comparison fair.                                                  | Not started |
| 6   | Tag the reference                              | `git tag pico-reference`, then push the tag.                                                                                                                                                                                                  | The tag is visible on GitHub.                                                                                                 | A fixed point that can always be rebuilt and compared against, however far the port moves.                                                              | Not started |
| 7   | Install ESP-IDF                                | One pinned version on every machine, recorded in SETUP.md.                                                                                                                                                                                    | `idf.py --version` matches everywhere.                                                                                        | A toolchain mismatch is what broke the original Pico build; pinning prevents a repeat.                                                                  | Not started |
| 8   | Confirm the Super Mini hardware                | Read the chip marking for flash and PSRAM size, list the usable GPIOs against the board pinout, and identify the console USB port.                                                                                                            | Recorded in SETUP.md.                                                                                                         | Confirms the module named in D1 and fixes which pins the port can use.                                                                                  | Not started |
| 9   | Add an ESP-IDF project to `s3-port`            | An empty `esp32s3/` project that prints a line over USB.                                                                                                                                                                                      | `idf.py build flash monitor` shows the line on the Super Mini.                                                                | Proves build, flash and serial output work before any framework code is involved, so later failures are code problems rather than setup problems.       | Not started |
| 10  | Introduce the HAL on the Pico side             | Define `hal.h` (time, delay, console input, GPIO write, PWM) with a Pico implementation, and switch `scheduler`, `repl`, `rules`, `rule_action`, `mqtt_config_parser` and `inference_manager` to call it.                                     | The Pico passes the full parity checklist again.                                                                              | Refactoring while the Pico can still verify it keeps refactoring mistakes separate from porting mistakes.                                               | Not started |
| 11  | Write the S3 HAL                               | `hal_esp32s3.c` using `esp_timer_get_time`, `vTaskDelay` / `esp_rom_delay_us`, and the USB-Serial-JTAG console.                                                                                                                               | A test prints timings and echoes typed input on the S3.                                                                       | The shared files then have everything they need to run on the S3 without edits.                                                                         | Not started |
| 12  | Compile the shared files into the S3 build     | The ESP-IDF build compiles the existing files in place, with no copies: the six with no Pico dependency (`rule_expr`, `config_parser`, `output_format`, `bus_if`, `mqtt_json_parser`, `sensor_bridge`) plus the HAL-based files from task 10. | The S3 build compiles, and `git diff` shows no edits to the six dependency-free files.                                        | The core portability evidence: identical source files building for both boards.                                                                         | Not started |
| 13  | Port the main loop and REPL                    | The loop yields on every pass so the ESP-IDF watchdog does not reset the board.                                                                                                                                                               | `SHOW`, `RUN`, `STOP` and `HELP` give the same responses as on the Pico.                                                      | The REPL drives every later test, and this proves the main loop runs stably under FreeRTOS.                                                             | Not started |
| 14  | Port the scheduler and GPIO digital mode       | The same config as on the Pico, with only the pin number changed.                                                                                                                                                                             | Same output format as the Pico; toggling the pin changes the first byte.                                                      | The first complete path on the S3: config, scheduler, driver and output working end to end.                                                             | Not started |
| 15  | Port the remaining GPIO modes                  | Pulse, counter and onewire.                                                                                                                                                                                                                   | Each GPIO row of the parity checklist is reproduced, and the HC-SR04 responds to distance.                                    | Completes the GPIO bus.                                                                                                                                 | Not started |
| 16  | Port I2C                                       | ESP-IDF I2C master driver.                                                                                                                                                                                                                    | The checklist's I2C sensor returns real data.                                                                                 | Second bus proven.                                                                                                                                      | Not started |
| 17  | Port UART                                      | ESP-IDF UART driver.                                                                                                                                                                                                                          | The checklist's UART sensor returns data.                                                                                     | Third bus. | 18  | Port rule actions                              | Log, GPIO output, and PWM via LEDC.                                                                                                                                                                                                           | A checklist rule fires the same action on the S3.                                                                             | The rule engine is the application logic, so identical behaviour here is the portability claim itself.                                                  | Not started |
| 19  | Port WiFi and MQTT                             | `esp_wifi` and `esp-mqtt`: telemetry, configuration and commands over MQTT, and the sensor bridge.                                                                                                                                            | Telemetry reaches the broker, and a config sent over MQTT is applied.                                                         | Networked configuration is part of the framework. It is the highest-risk area, so it follows the proven local core.                                     | Not started |
| 20  | Port model storage and inference               | A flash partition read through `esp_partition_mmap`, `esp-tflite-micro` in place of `pico-tflmicro`, and the `send_model.py` upload path.                                                                                                     | A model uploads and loads, and `infer.run` returns a score.                                                                   | Inference is part of configpico2wedge. D1 ports the pipeline and leaves the model itself unchanged.                                                     | Not started |
| 21  | Fill in the parity table                       | The S3 column for every row: pass, partial or fail, each with a reason.                                                                                                                                                                       | No empty cells.                                                                                                               | D1's core evidence.                                                                                                                                     | Not started |
| 22  | Write the not-portable list                    | Every Pico-specific call, what replaced it, and anything that could not be abstracted.                                                                                                                                                        | Every rewritten file is covered: the three bus drivers, `main`, `mqtt_telemetry`, `mqtt_model_transfer` and `tflite_wrapper`. | A required D1 deliverable.                                                                                                                              | Not started |
| 23  | Merge `s3-port` into `main`                    | Merge, tag, then build from a fresh clone.                                                                                                                                                                                                    | A fresh clone builds for the S3 by following SETUP.md alone.                                                                  | Proves the port is reproducible for the whole team, not just on one machine.                                                                            | Not started |
